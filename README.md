# AI Radar · GitHub AI 趋势榜

每天收集 GitHub AI 项目的官方数据，用中文介绍项目用途，并提供年榜、月榜、周榜、日榜和历史总榜。默认打开最新日榜 TOP 30，支持独立的自定义起止时间区间榜单，以及项目分类、能力标签、语言和使用方式筛选。

- 公开仓库：[MUZI-LYY/ai-trend-radar](https://github.com/MUZI-LYY/ai-trend-radar)
- 网站部署地址：[AI Radar](https://muzi-lyy.github.io/ai-trend-radar/)
- 产品需求：[PROJECT_BRIEF.md](PROJECT_BRIEF.md)
- 数据来源：[DATA_SOURCES.md](DATA_SOURCES.md) · [竞品调研](COMPETITIVE_RESEARCH.md)

## 榜单怎么算

| 榜单 | 排序依据 | 时间范围 |
| --- | --- | --- |
| 年榜 | 官方 Star 历史日统计之和 | 来源日期所在自然年，截至最近完整统计日 |
| 月榜 | 每日 TOP 30 上榜记录去重，累加上榜日的新增 Star | 所选自然月，截至月末或最新完整统计日 |
| 周榜 | 每日 TOP 30 上榜记录去重，累加上榜日的新增 Star | 周一开始的自然周，截至最近完整统计日 |
| 日榜 | 官方 Star 历史日统计 | 最近完整来源统计日 |
| 历史总榜 | 仓库当前累计 Star | 所选采集快照时的累计值 |

周期指标来自 GitHub 官方 `stargazers/history`，不等于两次累计 Star 相减的净增长。日期按接口 `week` 时间戳的 UTC 日期展开，源统计日边界不保证恰好是 UTC 或北京时间午夜。当天未完成的来源统计日不进入排名；缺失数据不补零。所有榜单只在本站收录范围内比较，Star 表示关注度，不代表质量或实际用户数。

周榜和月榜分别汇总所选自然周或自然月每天日榜 TOP 30 的上榜记录：按仓库 ID 去重，只累加上榜当天的新增 Star；未上榜日、周期外增长和累计 Star 不影响汇总分数。同分按仓库名排序。周榜和月榜展示上榜天数、最佳日榜名次和日榜新增合计，并提供逐日来源。所选截止日与当前查看的日榜一致，较早日期优先使用已存日榜；最新视图和历史回溯中，没有已存日榜的日期按官方日值回算 TOP 30 并明确标注。缺失的已存日榜读取失败时不静默替换为回算；快照视图不补造未保存的日榜。项目详情中的整周、整月新增仍保留完整周期统计，与“日榜新增合计”分别标注。

首页日榜只展示正增长的全站前 30 名；“全部项目数据”可查看完整收录集合。收录项目数不是当天新建项目数；页面单独显示当日有增长和零增长的数量。点击品牌或“发现榜单”回到最新日榜。

日榜的“在榜时间”指连续进入本站全站日榜前 30 名的天数，从首次真实保存的每日榜单开始计算。缺少相邻日期、落榜后重新上榜均从 1 天开始；同日刷新不累计，搜索或分类筛选也不改变全站在榜记录。

周榜提供年份和 ISO 周次选择（周一至周日，跨年周按周四所属年份归属），月榜提供年份和月份选择，年榜提供年份选择。每个榜单独立记住所选周期；未结束周期截至最新统计日，不提供未来周期。

“自定义时间”独立提供区间榜单：选择开始和结束日期（含两端），按区间内的新增 Star 独立排序。该选择不改变日榜、周榜、月榜、年榜或历史总榜；切换固定榜单保留其所选周期，未选择时展示最新周期。缺少区间完整日数据的项目不参榜，真实零增长保留为零。已存快照数据继续保留供周榜和月榜逐日来源核对，不再提供重复的历史折叠入口。首轮扩充优先补齐 2026-01-01 至 2026-09-13 的 256 个来源日期，收录从 106 扩至 600 个项目，共 142,114 条 2026 年官方日统计；600 项均从年初或创建日起连续覆盖。原有 74 项的 2025 年历史仍保留（23,955 条），该轮所有年份合计 166,069 条。此后按真实来源持续增加，当前数量和覆盖范围以页面及 `public/data/history-index.json` 为准。年度覆盖明细保存在历史索引中。回溯页依据这些日值重算当前收录项目的日、周、月、年增长；只纳入所选日期已经创建的仓库，完整周期缺失时不参榜。回溯使用当前分类与介绍，存在当前收录范围偏差，不声称是当时的 GitHub 全量榜或本站真实快照；当时累计 Star 留空，增长同分按仓库名排序，也不计算实际在榜天数。

历史总榜和历史快照是两件事：总榜比较累计 Star；快照保留当时的数据、分类和介绍。官方 Star 历史可以提供过去的周期统计，但不能还原本站上线前的榜单、收录范围、分类或在榜天数。没有保存的日期不会生成虚构快照。

## 项目介绍与分类

136 个项目提供基于来源整理的中文编辑介绍（原有 106 项保留，本轮增加 30 项），详情包含具体工作流程、应用场景、功能解释、适合人群、上手步骤、准备条件、项目特有限制和 README 来源。榜单行直接展示概述节选，能力说明不再只重复标签。项目按主要用途分为 10 个方向，并带有能力标签、项目形态、使用方式、语言及维护状态。

人工整理内容保存在 `data/editorial.json`，自动采集优先保留这些修正。未来新发现项目先通过规则和 README 提供初步介绍、分类及标签，并标记为待核实；当前没有接入 LLM 自动生成中文摘要。首轮其余 464 项提供按 README 功能、条件、上手及限制段落整理的原文说明，保留出处，明确区别于中文编辑解读。另有 317 项用途分类覆盖保存在 `data/classification-2026.json`；只核对分类不会把说明标成人工精编。维护者核对官方材料后可补充编辑记录，再运行：

```bash
python3 -B scripts/enrich.py
python3 -B scripts/validate_data.py
```

更新编辑内容只应用到最新数据，不改写已经保存的历史快照。明显无关的项目可加入 `data/excluded.json`。

## 本地运行

需要 Node.js 22.13 或更高版本、npm、Python 3。采集本地数据时可使用已登录的 GitHub CLI（`gh auth login`），或通过环境变量提供有权读取公开仓库的 `GITHUB_TOKEN`。前端直接读取现有 JSON，运行网站不需要令牌。

```bash
npm ci
npm run dev
```

默认本地地址为 `http://localhost:5173/`。生产构建与检查：

```bash
npm run test
npm run lint
python3 -B scripts/validate_data.py
npm run build
npm run preview
```

重新采集（当天已有快照时，`--refresh` 只更新最新数据）：

```bash
python3 -B scripts/discover.py --max-requests 24
python3 -B scripts/collect.py --batch-size 600 --new-limit 40 --no-discover --refresh
```

补充 2026 年历史（断点重跑复用已取得的日期，保留既有的更早年份）：

```bash
python3 -B scripts/backfill_history.py --start 2026-01-01
```

补充完整 2025 年（只请求缺失项目，保留 2026 年数据，每十个项目保存一次断点）：

2026-09-15 补采结果：当前收录 880 个项目中，679 个在 2025 年已经创建；这 679 个项目均从 2025 年初或其创建日连续覆盖至年末，共 222,920 条 2025 年日统计。本轮新增 164,744 条，完整覆盖从 90 个项目增加到 679 个。2026 年既有的 207,004 条日统计保持不变。2026 年创建的 201 个项目不加入 2025 榜单；这是当前收录集合的历史回溯，并非当年保存的全站快照。

```bash
RADAR_REST_REQUEST_LIMIT=2500 python3 -B scripts/backfill_history.py --start 2025-01-01 --end 2025-12-31
```

`--end` 指定补采截止日，不会截断其他年份。项目创建前的日期不补零，缺失来源保持缺失；存在未完成项目或请求错误时命令返回失败，重跑继续补齐。请求预算是单次运行额度，不限制最终收录数。

每日采集会把新获得的日值合并到历史文件，保留较早的已验证数据；新收录仓库的早期历史不足时，运行上述命令补全。不会把当前仓库资料写成过去的采集快照。

不设总收录上限。`--no-discover` 只跳过发现步骤，仍消费已保存的候选队列。`--batch-size` 只限制单轮处理量，`--new-limit` 在该批次内为新候选保留名额；已有数据本期完整时跳过重复请求，待更新项目按最早尝试时间轮转。未完成候选和旧项目保留到后续批次。`--force-refresh` 可在批次内重查本期已完整项目。不要把令牌写入代码、JSON、Git 提交或前端配置。

## 自动更新与发布

`.github/workflows/update-and-deploy.yml` 在 GitHub Actions 中运行：

1. **每小时第 17 分钟**继续发现、收录和更新，保存 JSON；北京时间 08:00 后来源统计日推进时，保存对应日期的首次快照。
2. 验证数据并提交变化到仓库。
3. 构建静态网站，发布到 GitHub Pages。

推送到 `main` 会验证、构建和部署已有数据。手动拉取新数据：在仓库 **Actions → Collect AI trends and deploy → Run workflow** 中选择 `main`，默认继续未完成批次；需要重查本期已完整项目时勾选 `force_refresh`。手动刷新不会重写当日已保存的历史快照。

初次部署需在仓库 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**。Actions 使用仓库内置的 `GITHUB_TOKEN` 读取公开数据和提交更新，不需要另外配置长期个人令牌。工作流包含所需的仓库写入和 Pages 发布权限；组织策略仍可能限制这些权限。

GitHub Pages 只负责托管静态页面，后台采集由定时启动的 Actions 完成，所以不需要购买或运行常驻服务器，也不依赖本地电脑持续开机。定时任务可能因平台排队而延迟，不是准点保证；公开仓库连续 60 天无活动时，GitHub 可能停用定时工作流，可在 Actions 中重新启用。失败应查看工作流日志和网站更新时间。

收录数量由实际发现和核验结果决定，不设 600、700 或其他总量目标。Actions 每轮最多处理 600 个仓库，其中为至多 40 个新候选保留名额，每小时继续下一批。发现与采集分开：26 个主题按 Star 分段、排序及分页游标轮转，包含 0 Star 项目，高 Star 段不设数值上界。候选按稳定 ID 去重，队列和失败重试日期持久保存在 `data/discovery.json`。超出一轮额度的工作保留，不因已收录项目增长而永久挤掉新候选。

页面显示实际已发现、已收录、待核验和本期完成更新的数量。发现数包含尚未核验的候选，搜索主题仍可能漏掉未标注的 AI 项目，因此不宣称覆盖 GitHub 全量。原有 600 个项目只是首轮历史补采结果。

仓库元数据用 GraphQL 每批 25 项获取；Star 历史复用旧日值，每天通常只刷新最近一页；README 每周分片轮换。采集 REST 硬预算为 940 次，另留发现查询预算，适应 Actions 内置令牌每仓库每小时 1,000 次 REST 配额。超过预算的项目保留旧记录并标出未更新，绝不伪造新增长。搜索、GraphQL 和次级限流仍独立生效。

## 文件结构

```text
src/                          React 网站及排名交互
scripts/collect.py            官方数据采集与归档
scripts/enrich.py             应用中文编辑资料
scripts/validate_data.py      发布数据检查
data/editorial.json          编辑介绍、分类与标签
data/excluded.json           排除的仓库
public/data/latest.json       最新数据
public/data/snapshots/         每日保存的历史快照
public/data/index.json        历史日期索引
public/data/board-history.json 全站日榜前 30 名记录
public/data/history.json       回溯用官方每日 Star 统计
public/data/history-index.json 可回溯日期索引
scripts/backfill_history.py    历史补采与每日增量合并
tests/                        统计边界与数据逻辑测试
.github/workflows/            自动采集和 Pages 发布
```
